1. 帧是一个小黑盒，装有函数的含义（具体操作过程）

### 选择名称
- 参数与函数名称应是小写的，单词之间用下划线连接，两者名称之间要相互映衬，如果作用明确的话，大写首字母表示也是可以的
### 局部赋值
- 局部赋值是将名称与当前环境的第一帧相绑定，没有增强函数的表达能力，但与控制语句相联用时，会显得更加简洁
  
  ### 函数抽象
- 聚焦于功能而省略其实现
- 三个核心要素
1. 域：输入范围
2. 值：输出范围
3. 意图：输入到输出的关系

## 文档
- docstring
函数体中缩进，引用三个引号，第一行描述函数的任务，后续几行描述参数的意义并解释函数的意图
- 参数默认值
函数在定义阶段就可以为形参设置初始值，这样的话更具体，从而容易检查，也方便检察者修改
```python
>>> def pressure(v, t, n=6.022e23):
        """计算理想气体的压力，单位为帕斯卡

        使用理想气体定律：http://en.wikipedia.org/wiki/Ideal_gas_law

        v -- 气体体积，单位为立方米
        t -- 绝对温度，单位为开尔文
        n -- 气体粒子，默认为一摩尔
        """
        k = 1.38e-23  # 玻尔兹曼常数
        return n * k * t / v

```
# 控制
### 语句
- 表达式会返回一些值，但不会改变解释器的状态，而执行语句会改变解释器的状态，语句本身不返回值，但会描述对解释器(环境)的一些更改，在较高的层面语句通过管理和组织表达式来控制程序
### 复合语句
- 复合语句是由一个或多个字句构成，其中子句又是以冒号结尾的单行头部以及缩进句体构成
```python
<header>:
    <statement>
    <statement>
    ...
<separating header>:
    <statement>
    <statement>
    ...
...
```
- 复合语句执行
运行一系列语句，先运行第一句，如果该句不是重定向控制语句，则执行语句序列的剩余部分。
- 实践指南
缩进时，所有的语句都要缩进相同的量，否则就会出问题

## 测试
- assert 语句：用于直接判断代码中的条件是否直接为真
```python
>>> def fib_test():
        assert fib(2) == 1, '第二个斐波那契数应该是 1'
        assert fib(3) == 1, '第三个斐波那契数应该是 1'
        assert fib(50) == 7778742049, '在第五十个斐波那契数发生 Error'

```
- doctest
通过docstring来实现验证：第一行是函数的单行描述，接着是一个空行，接下来写参数和函数的意图的具体描述
```python
>>> def sum_naturals(n):
        """返回前 n 个自然数的和。

        >>> sum_naturals(10)
        55
        >>> sum_naturals(100)
        5050
        """
        total, k = 0, 1
        while k <= n:
            total, k = total + k, k + 1
        return total

```
- 可以通过doctest模块来验证交互
```python
>>> from doctest import testmod
>>> testmod()
TestResults(failed=0, attempted=2)
```
如果仅想验证单个函数的 doctest 交互，我们可以使用名为 `run_docstring_examples` 的 `doctest` 函数。不幸的是，这个函数调用起来有点复杂。第一个参数是要测试的函数；第二个参数应该始终是表达式 `globals()` 的结果，这是一个用于返回全局环境的内置函数；第三个参数 `True` 表示我们想要“详细”输出：所有测试运行的目录。

```python
>>> from doctest import run_docstring_examples
>>> run_docstring_examples(sum_naturals, globals(), True)
Finding tests in NoName
Trying:
sum_naturals(10)
Expecting:
55
ok
Trying:
sum_naturals(100)
Expecting:
5050
ok
```

当函数的返回值与预期结果不匹配时，`run_docstring_examples` 函数会将此问题报告为测试失败。

当你在文件中编写 Python 时，可以通过使用 doctest 命令行选项启动 Python 来运行文件中的所有 doctest：

```python
python3 -m doctest <python_source_file>
```

有效测试的关键是在实现新功能后立即编写（并运行）测试。在实现之前编写一些测试也是一种很好的做法，以便在你的脑海中有一些示例输入和输出。调用单个函数的测试称为单元测试（unit test）。详尽的单元测试是良好程序设计的标志。
